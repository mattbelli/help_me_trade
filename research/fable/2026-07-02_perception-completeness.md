# Perception Layer Audit — what the agent sees, what it's blind to, how to finish PERCEIVE
*Fable 5 audit · read-only · 2026-07-02 · the PERCEIVE half of the Decision Engine.*

**Verdict:** a well-built *microscope* and a missing *wide-angle lens*. Per-symbol depth is genuinely strong (quote → levels → technicals → calibrated score in one call), the journal/my-trades honesty machinery is exemplary, the write surface is appropriately narrow. But the agent cannot **find** candidates (no screener), cannot **condition on regime** (FRED feed exists, invisible), cannot **read news** it already pays Finnhub for, and cannot **see its own calibration**. It grades one stock brilliantly; it cannot assemble a ranked slate. ~80% of the fix is "one registry line per feed" — the maintenance contract at `ai/perception/resources.py:407-411` was built for exactly this and hasn't been kept up.

## 1. Inventory — what the agent CAN see
**`get_context(symbol)`** (`context.py:214-359`): `quote` (price/change%/session/ext), `rvol` (vol-vs-expected), `session_nodes` (POC/VAH/VAL/PDH/PDL), `technicals` (sma50/200, vs_sma200%, RSI14, ATR14, dist-from-20d-high, trend — excellent), `fundamentals` (pe/eps/div/mktcap — **thin, no sector**), `earnings` (last/next), `decision_score` (calibrated win_prob/EV/CI/top_factors), `active_alerts`.
**`query(resource)`** (registry `resources.py:412-481`): `watchlists` (**symbols only**, no quotes), `strategies`, `price_alerts`, `proposals` (pending phone), `reports` (**200-char previews only**), `decision_journal` (its own calls: predicted vs resolved + honest insufficient-data floor — best-designed here), `my_trades` (net-cash + behavioral, paper excluded), `schwab_accounts` (real balances, `read_only:true`).
**Chat tools:** `get_portfolio_snapshot`, `get_agent_status`, `get_earnings_dates`, `get_option_quote`, `get_trade_history`, `get_performance_insights`, `web_search`, `search_memories`, `start_research`.
**Per-turn injection — mostly OFF:** the journal turn-context block is **dead code in the web chat** (`fetchChatContext` never sends `injectJournal`; `autoInjectMemories` defaults false). `list_capabilities` isn't registered in the frontend tool registry — the exact two-surface gotcha `PERCEPTION_LAYER.md:98-105` warns about; the self-describing manifest is invisible to live web chat.

## 2. Coverage gap — real feeds the agent CANNOT reach (ordered by REASON impact)
- **Screener / scans — the worst gap.** `signals/screener.py` (presets reusing the same technicals perception surfaces) + `/api/scanner/rvol` (~986-name universe) run UI-only. **The agent has no candidate generation at all** — it deep-dives only symbols someone names. A ranked-slate engine without a top-of-funnel isn't an engine.
- **Market regime — invisible.** `signals/regime.py:100-124` (term spread + VIX from FRED) is stored + already gates `vix_spike`, but there's no scope. The agent can't state what regime it's in — while the research flags regime gating as a top open question.
- **News — invisible despite being wired for the UI.** `afetch_company_news` + `/api/ticker/watchlist/news` exist; the agent's only news path is `web_search` (strictly worse). Reading text + writing the thesis is *precisely* the LLM's designated job — and its best text feed is hidden.
- **`strategy_signals` per symbol — planned, never built.** The check+rationale functions exist (`signals/strategy_kinds.py:42-146`); no symbol field group surfaces them. The agent can't say "dip_buy would fire here because —" about its own playbook.
- **Calibration verdicts — invisible.** `compute_calibration` grades predicted-vs-realized win% with Wilson CIs (`/api/journal/calibration`); the agent sees journal *outcomes* but not whether its *probabilities* are honest — the core trust metric.
- **Open orders — silently dropped (a BUG).** Snapshots store them + the tool promises them, but `_multi_account_context` (`tools.py:247-309`) never passes `open_orders` through → the agent proposes entries blind to resting orders → duplicate/conflicting proposals.
- **Rules write-without-read.** Can create rules (`propose_rule`) but can't list existing rules or firing history → arms duplicates, never learns whether any fired. Same for **notifications history** — "what happened while I was away" is the cockpit's core question and the agent can't answer it.
- **Partial:** managed-position exit detail (no stop/targets surfaced), sector/industry (no concentration awareness), Schwab equity history, chart drawings (user intent = high signal), research artifacts (can *start* research, never read finished reports), app-wide "who reports this week", executions ledger.

## 3. Enough to REASON? No — symbol-depth solved, market-breadth blind
Could a strong LLM fuse what's perceivable into a ranked, argued, calibrated slate? Not yet, for four concrete reasons: **(1) no funnel** (every discovery mechanism is UI-only; the watchlist arrives as bare symbols forcing N heavy `get_context` calls — a Schwab-burst hazard — to compare anything); **(2) no regime conditioning**; **(3) incomplete fusion inputs** (technicals excellent, fundamentals thin/no-sector, regime invisible, news text invisible, sentiment nonexistent — correctly); **(4) no self-calibration loop** (can't read the report grading its own win%, so it can't honestly hedge "my 60-70% bucket runs at 45%, n=12"). Striking: nearly all the missing input is **already computed** (scorer features, strategy checks, regime, screens, calibration) — the agent isn't missing computation, it's missing registry lines.

## 4. Write surface — narrow + safe, two honesty nits
Confirmed narrow: price-alert CRUD (validated), `propose_order` → proposal → `ExecutionService.submit` (rejects read-only accounts, excluded from the web planner, mobile intercepts to a pending phone proposal), trade-rules → human-approved proposals, chokepoint intact, no code/config/raw-DB writes. Two fixes: **(a) `propose_rule` is misnamed** — description promises an Approve/Reject card, but `execute_tool` calls `create_rule(enabled=True)` directly (arms immediately); acceptable risk-wise but the tool lies + pairs badly with no-read-on-rules. **(b) the manifest understates the write surface** (`list_capabilities` declares only the 3 price-alert actions, omits `propose_order`/`propose_rule`) — the agent's self-model of its own hands is stale.

## 5. Plan to complete perception — prioritized (mostly "wire an existing feed", ~20-50 LOC each)
**Tier 1 — Decision Engine unlocks:**
1. **`screener` resource** — wrap `run_scan`/`PRESETS` + the RVOL scanner reusing the cached/sp500-store bar getters (never bursts Schwab). *The single biggest step from "grade one stock" to "rank a slate."*
2. **`market`/`regime` scope** — wrap `market_regime()` + `regime_is_fresh()` (term spread, VIX, freshness). Trivial; regime-conditioned reasoning.
3. **`news` in the symbol scope + watchlist-news resource** — reuse `afetch_company_news` + the aggregation (cache bounds cost). Gives the LLM the text its narrative role needs.
4. **`strategy_signals` symbol field group** — evaluate the check+rationale pairs against an `EntryContext` built outside the scan loop. The agent cites its own playbook. Medium (composition, not new math).
**Tier 2 — trust + hygiene:** 5. **`calibration` resource** (wrap `compute_calibration`, trivial). 6. **Fix the `open_orders` drop** (bug-sized). 7. **`rules` + `rule_events` + `notifications` resources** ("what fired while I was away") + rename `propose_rule` honestly. 8. **Watchlist compact quotes** (reuse `/api/watchlist/market` so breadth doesn't cost N×get_context).
**Tier 3 — cheap completeness:** sector into `fundamentals` + a `sector_exposure` resource; full-body `reports` fetch + `research_artifacts`; `drawings`; `schwab_history` curve; managed-position exit detail; register `list_capabilities` in the frontend + update the manifest.
**Genuinely new (defer):** sentiment scoring (correctly absent — don't fabricate), breadth indices, a batch `score_symbols([...]) → ranked-slate` endpoint (mostly composition over the persisted bar store — really the first REASON artifact, built on Tier 1).

**The 3-4 highest-leverage:** **screener** (top-of-funnel), **market/regime** (conditioning), **symbol news** (the LLM's text half), **strategy_signals + calibration** (self-aware, honest playbook talk). With those wired, the loop the mission needs — *scan → shortlist → ground each symbol → condition on regime → score → rank → explain with calibrated humility* — becomes executable with today's tool surface, and REASON finally has something to fuse.
