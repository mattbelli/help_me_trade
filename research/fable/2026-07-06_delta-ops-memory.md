Scope: db-retention, memory overhaul P0+P1, the 07-02 ops-fix wave, statement-import/backup data-leak surface. Pre-existing carded items (board.json) and the 07-02 report's still-open backlog are deliberately not re-reported.*

## Verdict
The 07-02 ops wave and memory P0/P1 are substantially real — retention is correctly allowlisted away from everything the calibration-counts-everything rule protects, the token watchdog is honest now, backups are verified+watched, and the extractor/judge shipped what the plan promised. What the delta audit found is one deployment gap that turns a shipped fix into a **scheduled multi-day Schwab outage this week** (the live crontab still runs the old 6-day stride, and the new `--skip-if-fresh` guard deterministically skips the one run that would have saved it), plus two real holes in the memory trust fence: founder-**confirmed** memories are outside the judge's containment (an agent rewrite keeps `user_confirmed` authority), and the `save_memory` quote path is a judge-bypassing, injection-reachable guaranteed-ADD that is already injected into the propose-order-capable mobile agent every turn.

**Counts: 1 CRITICAL · 2 HIGH · 2 MEDIUM · 4 LOW.**

## CRITICAL-1 — The reauth fix shipped in code but not in the crontab; skip-if-fresh + the old stride = a *deterministic* missed re-mint, token dead ~Jul 9
The 07-02 CRIT-1 round made the reauth "daily-safe" (`--skip-if-fresh`, default ON, threshold **<5.0 days**, `scripts/schwab_reauth.py:588-590,603-607`) and documented the daily line in `deploy/crontab.example:12`. But the **live crontab still has the audited-and-condemned day-of-month stride**:

- `crontab -l` on serv: `0 6 */6 * * … scripts.schwab_reauth …` (runs on the 1st, 7th, 13th, …).
- Live token file: `creation_timestamp` = **2026-07-02 18:35 UTC** (age 3.99d at audit time).
- Next cron run **Jul 7 06:00** → token age ≈ **4.5 days < 5.0** → `[reauth] token fresh — skipping`.
- Next attempt after that: **Jul 13 06:00**. The refresh token dies **~Jul 9 18:35 UTC**.

So the guard added to make daily runs idempotent *interacts with the un-updated stride to guarantee the miss* — before the fix, the Jul 7 run would have re-minted. From ~Jul 9 evening to Jul 13+: all Schwab market data, RVOL, session-node, price alerts, EOD snapshots dark. The new SPY probe (`api/main.py:1060-1092`) will page after 3 consecutive failures — so it is not *silent*, but if the founder is away it is 3.5 days of dead data plus a headless-Playwright re-auth he may not be able to run remotely. BUILD.md (07-02 row, line 711) and HANDOFF.md:279 both flagged "⚠️ Human step: update the crontab line to daily" — four days later it hasn't happened, and nothing enforces it. **Fix: run `crontab -e` today (copy `deploy/crontab.example`), or better, have the in-app watchdog compare `auth_status().refresh_token_age_days` against the *next scheduled cron run* so a doomed schedule pages before the token dies, not after.**

## HIGH-2 — `user_confirmed` memories sit outside the judge's containment fence
The poisoning defence (`ai/memories/judge.py:175`) blocks agent-side UPDATE/SUPERSEDE only for `pinned` rows and `authority == "user_authored"`. The design's hard line (MEMORY_OVERHAUL_DESIGN.md §386) is that `user_authored` **or `user_confirmed`** directives/preferences are the tier allowed to shape proposals, and the widget's Confirm tap mints `user_confirmed` (`api/ai_routes.py:686-705`). Consequences, all code-verified:
- **Authority-preserving rewrite:** a judge UPDATE (`judge.py:202-205`) rewrites the row's *content* and deliberately doesn't pass `authority` — which means an agent-originated merge **keeps the row's `user_confirmed` badge on content the founder never confirmed**. The comment says "an agent UPDATE never *raises* it"; it also never *lowers* it. This is exactly the "LLM writes memories that steer decisions with stolen provenance" attack the audit brief asked about.
- **Silent retirement:** SUPERSEDE (`judge.py:206-219`) can mark a founder-confirmed directive `superseded` from any agent source (chat extraction, reflection, retrospective).
- **Chat archive:** `forget_memory` gates only pinned/user_authored (`ai/chat/tools.py:621`), so the copilot can archive a `user_confirmed` rule on a hallucinated "forget that".
Today the blast radius is the trust surface (widget shows Confirmed) and the judge's own neighbor context; when P2 turns injection on for the web copilot and confirmed directives start shaping proposals per §386, this becomes the poisoning path. **Fix: add `user_confirmed` to the containment check in `_apply` and to the `forget_memory` gate; demote authority to `agent_inferred` on any agent-side UPDATE whose merged content differs.** The golden set (`tests/fixtures/memory_golden.json`, "protected-directive-not-superseded") only tests `user_authored` — add the `user_confirmed` twin.

## HIGH-3 — `save_memory` with a quote is a judge-bypassing guaranteed ADD, and it's already injected into the propose-order agent every turn
Any `save_memory` call carrying a `quote` gets `source="user_explicit"` (`ai/chat/tools.py:581-583`), and user_explicit candidates are **never NOOPed and never dropped** — even when the judge fails or returns garbage (`judge.py:152-154, 277-279`). The quote is a model-controlled argument; the code comment admits it is "a model-attested argument, not a server-verified transcript match." So the chain is open: attacker text in a `web_search` snippet (the chat agent's one attacker-reachable input) → agent calls `save_memory(content="directive: …", quote="…")` → admission bar bypassed, stored forever → `mobile_agent.py:129` injects `turn_memory_context(user_text)` **unconditionally** into the *system* block (`format_memory_context_block`, `ai/chat/context.py:26-37`) of the one agent allowed to `propose_order`. Authority containment held (stays `agent_inferred` — good, tools.py:579-584), and every proposal still dies at the human-approval chokepoint, so money can't move on this alone — but it manufactures durable, founder-voiced instructions ("their exact words", per the tool description and mem-chip trust surface) that steer what lands on his phone. **Fix: cap/flag `user_explicit` writes per session; verify the quote server-side against the actual transcript (the code comment already names this as the condition for trusting quotes) before granting never-NOOP semantics; render unverified quotes as "agent-claimed" in the widget.**

## MEDIUM-4 — The learn loop fails silently: a flaky judge/extractor LLM = memory quietly off, invisible to /health
By design the judge "prefers forgetting" (`judge.py:272-279` drops all agent candidates on LLM/parse failure; `memory_extract.py:128-130` likewise). Correct bias — but the failure signal is a single `logger.warning`. There is no counter, no job in the registry, nothing in `/health` (`api/main.py:1540-1556` — jobs, poll, backup age only). Given the documented DeepSeek flakiness (json_mode empty content, reasoning-eats-max_tokens) a misconfigured/degraded provider means reflection, retrospective, journal-review and chat extraction all silently stop writing memories for weeks — indistinguishable from "nothing worth remembering," which the extractor explicitly calls the expected output. Partial judge output has the same property: decisions parsed for some indices, the rest dropped with only a WARN (`judge.py:117-134,156-160`). **Fix: count judge failures/drops into a registered heartbeat job so the staleness watchdog pages on a dead learn loop.**

## MEDIUM-5 — The off-box backup leg has no watchdog on either side
On-box is now solid: `.backup` + `PRAGMA integrity_check` + config tarball + fail-loud (`deploy/backup-db.sh`), and the in-app watchdog pages when the newest **local** backup is >26h old (`api/jobs.py:161-172`; live dir verified current through Jul 6 03:00). But the off-box copy is a *pull* from mattpc (Windows Task Scheduler, script comment lines 37-42), and nothing monitors the pull: serv can't see whether mattpc fetched, mattpc doesn't page, and card #36 closed as a one-time "verify the PC pull folder." A dead scheduled task (Windows update, sleeping PC, Tailscale key expiry) silently reverts CRIT-2 to "backups never leave the box" — discovered only at restore time. **Fix: have mattpc's pull script touch a marker file back on serv (or write a `last_pull` timestamp the watchdog can age-check); page at >48h.**

## LOW findings
- **LOW-6 — Stale-client token clobber (lineage, not clock).** `_write` (`brokers/schwab_auth.py:174-188`) now preserves the on-disk `creation_timestamp` (good — the watchdog stays honest) and factory caches invalidate on token-file mtime (`brokers/factory.py:115-139`). But a client *instance* held across the cron re-mint (built pre-mint, referenced outside the caches) that refreshes afterwards writes its **old-lineage token under the fresh clock**. Bounded by the SPY probe and by `schwab_accounts.py` building a fresh client per fetch (line 114) — narrow race, worth a token-value equality check in `_write`.
- **LOW-7 — UPDATE provenance drift.** A judge UPDATE rewrites `content` but keeps the row's original `quote`/metadata (`judge.py:203-205` → `update_memory`), so the "exact words" provenance no longer matches the content it supposedly evidences. Clear the quote (or append merge provenance to metadata) on content-changing UPDATEs.
- **LOW-8 — Keeper rows are start-of-period equity.** Retention keeps the *earliest* run per hour/day (`db/retention.py:37-95`), i.e. ~midnight/pre-market snapshots. No current reader looks past 7 days (`list_equity_history` days=7; analytics latest-only), so this is a design note: any future long-horizon equity curve built on keepers will plot prior-close-ish values. Prefer keeping the *last* run per bucket if that reader ever appears.
- **LOW-9 — In-window BUILD.md rows continue the carded #38 pattern.** The 07-02 Rounds 9-11 BUILD.md entries commit real realized-P&L figures from the funded Schwab accounts (exact day/week dollar amounts) into a tracked doc. #38 ("Stop writing real account figures into tracked docs") is carded backlog, so not re-reported as new — noted only because the pattern kept accruing *after* the card existed.
