# Financial-Data-Integrity Audit — help_me_trade
*Fable 5 audit · read-only · 2026-07-02 · verified against the live ledger (`data/trading.db`: 4 Schwab real + 3 Alpaca paper, 527 events; zero cross-source dupes today).*
*Two specific position dollar figures redacted vs raw (keep finances out of tracked docs).*

## 1. Trust map
**Genuinely trustworthy (verified):** net-cash realized on fully-closed symbols (`db/realized_pnl.py` — order-independent signed-`amount` sum, Decimal, honest `closed/open_long/incomplete` statuses; the $[XX]k PLTR / $[XXX] GME proceeds-without-basis correctly quarantined `incomplete`); the dedup layer (`db/trades.py` unique `(account_id, external_key)` + partial-unique `broker_txn_id`; sync refuses to advance a cursor over a gap); the snapshot-aggregate firewall (`api/main.py:1366-1394`, single money_type); the flat-days-only equity curve (`signals/schwab_equity.py`, ET dates, all-cash-days-only); Schwab `day_pl` mechanics — *but see H3, it also captures deposits.*
**Assumed, not enforced:** the label join between `/api/schwab/accounts` and `trade_accounts` (nothing pins them); "JSON export ends on a complete day"; "Schwab txns always carry `activityId`"; "Alpaca is the only `poll_runs` writer".
**The weak joints are all in scope resolution and LLM context assembly — not the ledger itself.**

## 2. Ranked correctness risks
### CRITICAL
**C1 — The LLM's performance context blends paper + real (firewall breach, LIVE today).** `/ai-context` (`api/performance_routes.py:37-47`), chat `get_trade_history`/`get_performance_insights` (`ai/chat/tools.py:544-575`), and `ai/retrospective.py:141-153` call `ai_performance_context`/`list_trade_events`/`trade_summary_stats` with **no `real_only`**, default `account_id=None`. Inside `db/analytics.py:596-624` the dashboard, `symbol_trade_stats` (has *no* real/paper param at all, `db/trades.py:548`), `_round_trips_in_period`, and open-lots run unscoped → **Alpaca sandbox fills summed into "realized_closed", win rates, top_symbols, behavioral stats presented to the agent as the founder's real track record** — and seeded into retrospective lesson-memories. Fix: route every entry through `resolve_perf_scope` (default `(None, True, False)`) + add `real_only/paper_only` to `symbol_trade_stats`.

**C2 — "Unrealized" in LLM context marks real lots against the paper snapshot.** `db/analytics.py:625-643` calls `get_latest_snapshot()` with no broker; Schwab never writes `poll_runs`, so it's the **Alpaca paper snapshot**. `compute_unrealized` reports paper `unrealized_pl` as `broker_unrealized_pl` beside blended ledger lots + injects paper-only symbols into `by_symbol`; MTM `latest_prices` from the same paper snapshot. A paper/real chimera. Fix: pass `broker="alpaca"` only for paper scopes; for real, mark against `get_schwab_accounts_sync` positions or omit.

**C3 — Silent scope substitution in the account resolver.** `db/account_scope.py:53-131`: unknown `acct_` id, Schwab API failure (Akamai WAF is a known reality), or missing/renamed label → **falls back to aggregate-all-real with only a server log**. Select "Roth (Personal)", Schwab hiccups → the page shows all-four-accounts numbers under that label — plausible and wrong. Label join is fragile: `_labels()` is a free-form dict, `next()` takes first-match, so a duplicate friendly label (the 2nd Roth) mis-maps. Fix: return an explicit `scope_resolution: "fallback"` field the UI must render; join on `last4`/`broker_external_id` (stamp `last4` into `trade_accounts`), not label.

### HIGH
**H6 — `_find_ev_bucket` fabricates EV from the top bucket.** `signals/decision_scorer.py:76-87`: a `win_prob` outside every bucket returns `ev_table[-1]` — an out-of-range score inherits the **highest** bucket's EV/CI. That EV flows into the **phone proposal** (`signals/push.py:378-383` via `trading/proposals.py:348`) — the approve/reject decision this app exists for. **Exactly the "fabricated win%" the mission forbids** — the single most mission-hostile number in the codebase. Fix (5 lines): return `None` on no match; also `None` (not `0.0`) for missing `base_rate`/`brier`.

**H1 — Period realized P&L structurally excludes cross-boundary closes.** `db/analytics.py:509-530`: headline `realized_pnl` = `realized_summary(period_trades)` — events **inside the window only**. Buy Jun 20, sell Jul 1, view "month" → July has a sell-only symbol → `incomplete` → excluded. Day/week/month realized systematically understated; the note ("needs Schwab Realized G/L") is a false reason. Fix: compute period realized from full-history recon deltas (net_cash at period end − start for closed symbols).

**H2 — Demoted FIFO dollars escape the demotion.** (a) `signals/sector_breakdown.py` serves raw FIFO per-sector `realized_pnl` with no approximate flag; (b) `performance-page.tsx:290-298` sums FIFO `rt.pnl` for the by-symbol chart; (c) `ai/perf_context.py:12-30` strips only three trade lists — `approximate_fifo.profit_factor.gross_wins/losses` + `approximate_fifo.realized_pnl` survive into LLM context + retrospective. Fix: strip dollar aggregates in `sanitize_perf_context`; label sector/symbol figures `pnl_basis: "fifo_approximate"` end-to-end.

**H3 — Schwab `day_pl` includes deposits/withdrawals.** `brokers/schwab_accounts.py:146-150`: `day_pl = liq − initialBalances.liquidationValue`. An intraday $10k ACH shows as +$10k "Day P&L" on the toolbar and is **persisted** into `schwab_account_daily`. Fix: subtract same-day non-TRADE cash movements (Transactions API is already pulled), or flag days with transfers.

**H4 — API-synced trade dates are UTC, not ET.** `trading/sync.py:119-123` takes `.date()` of the ISO timestamp **without tz conversion** (contrast the correct `astimezone(_ET)` in `schwab_equity.py`). A fill after 8pm ET books to the next day; `resolve_period("day")` (now correctly ET) then misses it today, shows it tomorrow. `end = date.today()` (`sync.py:338`) is server-UTC; `settlementDate` fallback can book T+1; JSON dates are Schwab-local — two sources, two day conventions. **This is the write-side complement to the recently-shipped read-side ET day-fix.** Fix: mirror `_tx_et_date` in the sync parser.

**H5 — Multi-leg spreads & assignments corrupt per-symbol truth.** (a) `trading/sync.py:87` collapses a spread to its largest leg, attributing the whole `netAmount` to one symbol + **dropping other legs' quantities** → per-symbol recon/FIFO for the dropped leg is one-sided. (b) `imports/schwab_transactions.py:20-59`: `"assigned"`/exercise → `"other"` → excluded from recon/FIFO → an assigned short-put premium sits `incomplete` forever, understating realized. (Dead `journal→"transfer"` branch at `:57`.) Fix: synthesize per-leg events from `transferItems`; map assigned/exercised to closing events like `expired`.

### MEDIUM
**M1** `parse_dollar` turns garbage → $0 silently (`imports/money.py:24`); `record_schwab_daily` `or 0` writes $0 equity on a missing field — count/log failures, store NULL not 0. **M2** weekend/after-midnight snapshot rows repeat Friday's `day_pl` → double-count when summing `/api/schwab/history`. **M3** sync pulls only `TransactionType.TRADE` → dividends/interest never enter the ledger going forward. **M4** JSON-boundary hard floor can leave a silent unfetchable gap on the boundary day — add a one-time reconciliation count. **M5** `get_latest_snapshot(unknown id)` → latest snapshot of *any* account (`db/sqlite.py:481`); `sector_breakdown._resolve_positions` hits this → another account's positions under the selected one. **M6** stale Schwab cache (`{**cached, "stale": True}`) is never checked by the resolver/perception/sector → hours-old balances shown as live to the LLM. **M7** `real_only` is a denylist ("not-alpaca = real") — a future sandbox broker silently lands in the real track record; use an allowlist / `money_type` column.

### LOW
**L1** equity curve skips a hash-missing account's txns but keeps its liquidation in the anchor → pre-window points shifted. **L2** no futures point-multiplier anywhere; history not imported — "all"-period totals incomplete for a futures trader. **L3** `limit=100_000` silent truncation in every analytics query — fine at 527, a time bomb at scale. **L4** `period="custom"` with no dates → all-history silently. **L5** dead `_close_long_lots` (`db/fifo_round_trips.py:97`). **L6** `/api/performance/calendar` + `/symbols` bypass the resolver → same blend family as C1, UI-facing.

## 3. The firewall — attempts to break it
**Sound:** `_aggregate_account_snapshots`; `/api/schwab/accounts` totals; `/api/performance/dashboard` (via resolver); `sector_breakdown` (resolver ledger side + Schwab-or-one-paper positions); perception `my_trades` (denylist); `schwab_equity_curve`; `list_equity_history`.
**Paths that DO blend paper+real:** (1) `/api/performance/ai-context`; (2) chat `get_performance_insights` + `get_trade_history`; (3) `generate_retrospective_report` default; (4) inside `ai_performance_context` even when `account_id=None`: `symbol_trade_stats` (no filter exists), `_round_trips_in_period`, open-lots `history_events`, and the paper-snapshot `unrealized` block; (5) `/api/performance/calendar` + `/symbols`. **One root cause: `ai_performance_context` + two routes never learned about `real_only`. One fix closes the set.**

## 4. What the LLM can still say wrong (post-`_strip`)
1. A blended paper+real "realized_closed" as the founder's real track record (C1) — the strip never touches the *headline*. 2. FIFO dollars in disguise (`profit_factor` dollars, sector `realized_pnl`, `approximate_fifo.realized_pnl`). 3. Paper unrealized as broker truth (C2). 4. Stale balances as live (M6). 5. **A fabricated EV/win% on a proposal (H6).** 6. "Day P&L" that's actually a deposit (H3). 7. Understated period realized (H1) → the agent "learns" a losing month that was a winner, and `ai/retrospective.py` seeds those lessons into persistent memory. Well-guarded: incomplete positions, FIFO per-trade lists, sanitized win rates.

## 5. Fixes + tests, prioritized
1. **Close C1/C2 (one PR):** thread `real_only/paper_only` through `ai_performance_context` (+ `symbol_trade_stats`), default all LLM/route entry points through `resolve_perf_scope`; pin `get_latest_snapshot(broker="alpaca")` for paper scopes, drop/replace `unrealized` for real. **Test:** firewall property test — one alpaca + one schwab account, disjoint symbols; assert every public aggregate contains no symbol/cash from the other money_type; parametrize `account_id=None/"all_real"/"all_paper"`.
2. **Make resolver fallback loud (C3):** return `{resolved_account, fallback: bool}`; UI banner. Migrate join to `last4`. **Tests:** relabel drift, duplicate friendly label, Schwab-down.
3. **Fix H6 immediately** (`None` out-of-bucket; `None` for missing meta) — 5 lines, mission-critical. **Test:** win_prob below first bucket ⇒ `ev_pct is None`; push omits `evPct`.
4. **Period realized (H1):** full-history recon at boundary dates; assert `day+day+… == all` on a golden fixture that opens/closes across boundaries.
5. **Golden reconciliation test:** scrubbed fixture of the real export; assert `realized_closed` == hand-verified broker Realized G/L; GME/PLTR-style one-sided symbols land `incomplete` with $0. Nightly: sum(ledger net cash) vs Schwab cash delta.
6. **Sync hardening (H4/H5/M3/M4):** ET dates in `_schwab_transaction_to_event`; per-leg spread expansion; map assigned/exercised; widen `transaction_types` to dividends/interest. **Tests:** 8:30pm-ET fill → trade-date-ET; two-leg vertical → two events summing to `netAmount`; assignment closes the option lot.
7. **Money-path guards:** `parse_dollar(strict=True)` in importers; ruff/AST lint banning `float(` on money-named values under `db/`,`imports/`,`trading/`; NULL-not-zero + skip non-trading ET days in `record_schwab_daily`.
8. **Label remaining FIFO surfaces (H2):** `pnl_basis` on sector/symbol payloads; strip `profit_factor` dollars in `sanitize_perf_context`.

**Bottom line:** the ledger core + snapshot firewall are solid; the money is honest at rest. The dishonesty risk is concentrated in **scope resolution + LLM context assembly** — **C1–C3 plus H6** are where a wrong number most plausibly changes a real trading decision, and all four are small, testable fixes.
