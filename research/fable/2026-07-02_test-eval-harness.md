# Testing & Evaluation Posture — help_me_trade
*Fable 5 audit · read-only · 2026-07-02 · 142 test modules / 1,145 test fns; CI = ruff + pytest + `tsc`.*

## 1. Coverage reality map
**Genuinely well-tested (the right stuff):** `tests/test_phone_proposals.py` is the best file in the suite — double-approve idempotency, an *actual concurrency race* on the claim (`asyncio.gather` + delayed submit → asserts exactly one execution row), hash-mismatch, malformed-TTL fail-safe, Decimal-seam assertion. `test_risk_engine*` — one failure per gate + adversarial edges (limit-price valued against market, RTH-only quote fallback, oversell blocked, naked-option blocked, short-in-live blocked). `test_execution_service` asserts a persisted `rejected/error` row for every rejection (audit-trail behavior). `test_exit_engine` covers the auto-sell failure modes. Hygiene is excellent: `conftest.py` redirects the DB to a throwaway (tests wrote to prod DB *twice* before this), strips leaked creds, no network calls anywhere, deterministic. Research math is real (purged-k-fold non-overlap sample-by-sample; `test_tactical_fixtures` replays the live functions over golden FRED series bit-exact).

**Thin / theater risk:** `test_settings_kill_switch.py` is a 23-line cache test (the *effect* is covered elsewhere; the *UI* has none). `test_chat_brain.py`/`test_mobile_chat_stream.py` test plumbing with a **FakeLLM** — nothing tests whether the *real* model routes/grounds/refuses; closest thing to theater (good tests, but they imply the chat layer is covered — it isn't). `test_combined.py` tests calculator *mechanics*; the **headline book numbers live in gitignored `research/artifacts/*.json`** — tests prove the calculator works, not that the answer is reproducible. Hazard: `test_tactical_fixtures` uses `skipif(fixtures absent)` → if fixtures vanish, CI goes silently green.

**Untested surfaces, by risk × real-money exposure:** (1) **The LLM decision loop** (`frontend/app/api/chat/route.ts`, `chat-tools.ts`, `mobile_agent.py` against a real model) — zero evals/traces; the mission's product surface; a prompt/model change that misrouted 30% of queries would go unnoticed (no Langfuse, no golden set, no trace log — confirmed). (2) **The frontend approval/kill-switch UI** — ~40k lines TS, 0 tests, no runner even installed. The backend approve path is superbly tested; the *button the founder taps* has never been machine-exercised. (3) **Book-level backtest reproducibility.** (4) **Ledger truth** — `test_schwab_import` runs one fixture; no golden assertion that net-cash realized == a hand-verified broker Realized G/L. (5) **Dep drift** — `requirements.txt` 14 lines, all `>=`, no lockfile.

**Honest read:** the 1,145 tests DO translate to safety where a bad order could escape (chokepoint, risk gates, approval lifecycle, firewall — behavioral + adversarial, clearly fed by the ~16 review-caught bugs). But the distribution is inverted vs the mission: **~0 of 1,145 tests measure whether the agent's decisions are any good**, and the one surface a human touches is untested. *The suite protects against the agent doing something forbidden; nothing protects against it doing something stupid.*

## 2. Highest-ROI tests to add (ranked by risk-moved-per-hour)
1. **Golden net-cash reconciliation** *(small, highest truth-per-line)* — a **scrubbed** fixture (perturbed amounts, NEVER real data) with hand-computed Realized G/L; assert to the cent. Plus a local-only `tools/reconcile_check.py` (not CI) vs the real ledger + a founder-entered broker figure.
2. **RiskEngine property tests (Hypothesis)** *(medium, kills combinatorial holes)* — sweep side × qty × order_type × limit-vs-market × toggles × asset class. Invariants in §5. Add `hypothesis` dev-dep.
3. **Firewall property test** *(medium)* — "paper & real never blend in any public aggregate," parametrized over every read fn against randomized mixed-account DBs, so a *new* aggregate that forgets the flag fails by default.
4. **CI process guards** *(near-zero effort — this week)* — the `SAFETY-REVIEWED:` trailer check + pinned deps (§4). Move more risk than any single test below this line.
5. **Exactly ONE Playwright spec: the approval flow** *(medium-high — first spec pays the tooling tax)* — paper proposal → card renders → Approve → assert `order_executions` row + `executed`; optional kill-switch-blocks assertion. Ranked below the backend property tests deliberately (`approve_proposal` is the best-tested fn in the repo). **Stop at one spec — do not build a frontend pyramid** (widget churn = maintenance tarpit; the state audit said stop investing in desktop polish).
6. **Book-reproducibility fixture** *(medium)* — commit the (synthetic-ized) setups slice that produces the headline combined-book report; assert `combine_and_report` metrics within tolerance in CI. Flip the tactical `skipif` to a hard failure under `CI=1`.

**Do NOT test:** frontend breadth (widgets/themes/grid/charts — high churn, zero money risk); API-shape snapshots; coverage-% targets; the legacy `proxyLegacyPythonChat` path (dying); `route.ts` internals beyond the one E2E (mocking `streamText` tests the mock).

## 3. The LLM / decision-quality eval harness (the biggest gap — design)
Three layers, smallest real loop:
**Layer 1 — Tracing (build first, ~a day).** You can't eval what you can't see. Log every turn — `{ts, model, prompt_version_hash, system_context, tool_calls+args+results, final_text, latency, tokens}` — from the two finalize points that already exist (`finalizeChatTurn` in `route.ts:225`, `ai/chat/mobile_stream.py`). A `chat_traces` SQLite table is enough. **Langfuse (the R4 plan) = right destination, wrong first step** — for one user on a home box it's another service to babysit; the trace table gets 80% now, OTel-ify later.
**Layer 2 — Golden set (30–50 cases, `tests/evals/golden.jsonl`, ~2–3 days).** Each: `{prompt, expected_tools, forbidden_tools, expect_refusal, grounding}`. Categories: **tool routing** (~20: "exposure?"→snapshot; "buy 100 NVDA"→propose_order; "why'd I lose Tuesday?"→journal not web_search — score = exact set/sequence match, deterministic); **refusals** (~10: any "sell my Schwab / execute on my real account" → NO `propose_order` on a real account; shorting-when-off; "skip approval" — where the LLM could socially-engineer past a sound chokepoint by proposing the wrong thing); **grounding** (~10: regex-extract every number from the answer, assert each appears in that turn's tool results — **no LLM judge needed for v1**, mechanical, directly enforces "never fabricate").
**Layer 3 — Decision calibration over time (~2 days, mostly wiring).** The machinery exists (`db/decision_journal.py` records thesis + win_prob before outcome; `research/calibration.py` has the metrics). Missing: a periodic job bucketing journaled `win_prob` vs realized `outcome` → Brier + reliability table in the weekly report. "The agent said 62% on these 40 trades; 41% resolved winners" is the single most mission-aligned number the app can show — makes "calibrated never fabricated" *auditable* not aspirational.
**Where it runs:** CI runs only the deterministic pieces (grounding-checker unit tests, intent-regex, refusal-block presence). The full golden set needs a real model + keys → **nightly cron on serv** (`tools/run_evals.py`, ~$0.50/run), scorecard into SQLite, push on regression. Don't put keys in GitHub Actions.

## 4. CI / process hardening
1. **`SAFETY-REVIEWED:` guard** (an hour) — CI fails any diff touching `trading/` or `db/order_executions.py` without the trailer; mirror as a local pre-push hook. Machine-enforces the convention that's caught ~16 bugs (survives only on discipline today; the memory records a near-miss). 2. **Pin Python deps** (an hour) — `uv pip compile`/`uv.lock`; CI installs from it (today CI can silently change behavior with zero diff). 3. **Hypothesis** dev-dep; start with `tests/test_risk_engine_properties.py`. 4. **Mutation-testing spot-check (one-off, not CI)** — `mutmut` on `risk_engine.py` + `execution_service.py` once; surviving mutants tell you whether the assertions actually bite. 5. CI runs only the deterministic eval subset. 6. Convert golden-fixture `skipif`s to hard failures under `CI=1`.

## 5. Property-test targets for the safety/money core
1. **RiskEngine invariants** — no sell passes with `qty > held − pending_sells` (toggle off); toggle-on shorts still never pass in live; `passed==True ⇒ every gate pass/exempt`; `rebalance=True` exempts *only* the two count throttles; notional under max(limit,market) never exceeds the value cap; kill switch dominates. 2. **Firewall** — `real_only ∪ paper_only == all`, `∩ == ∅`, per-scope sums partition the total, table-driven over the function list. 3. **Atomic proposal claim** — N concurrent approve/reject → exactly one submit/execution row. 4. **Decimal seam** — arbitrary numeric inputs → every money/qty field is `Decimal`, DB TEXT round-trip lossless. 5. **Net-cash order-independence** — shuffling import order leaves realized P&L identical; re-importing a subset is a no-op (the property that makes "net-cash is truth" trustworthy vs sync retries). 6. **Exit engine single-flight** — concurrent ticks → at most one in-flight exit.

**Bottom line:** the safety chokepoint is protected by some of the best example-based tests in a solo project — spend nothing more on breadth there. Spend on **(a)** golden reconciliation + property tests that close combinatorial holes in the money paths, **(b)** two hours of CI hardening (trailer guard, lockfile), and **(c)** the eval harness (trace table → 30–50-case golden set → journal-calibration report) — because right now the app can prove it will never place a forbidden order, and cannot prove a single one of its ideas is worth taking.
