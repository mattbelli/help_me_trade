# Delta Audit — Idea-Generation Engine (2026-07-02 → 2026-07-06)
*Fable 5 adversarial delta audit · read-only · 2026-07-06 · scope: the idea-generation code shipped since the 07-02 audits (commits `612c1ca` setup_scan + deterministic structures, `7b6cf03` idea shadow-tracker, `82edb36` weekend-kill fix + outcomes widget, `f0d03e8` conviction lane, `64123b4` RVOL dedup persistence). Constitution audited against: the Decision Engine roadmap §1 — deterministic code owns every number, the LLM can only veto/shrink, win% never fabricated or flattered. Every finding below was code-verified with file:line; the CRITICAL and two others were reproduced live against the real modules before being reported.*

## 1. Verdict

The division of labor mostly holds where it was designed to: the LLM genuinely cannot move a number in the structure lane, the S/R levels are point-in-time with no lookahead, degenerate inputs fail closed, and the RVOL dedup fix is real. The rot is on the **judging** side, exactly where the constitution is most expensive to violate: the outcome tracker's own "win% must never be flattered" same-bar rule is defeated one sweep later (reproduced: `triggered` → `won` off the identical ambiguous bar), vetoed setups are never outcome-tracked so the veto half of veto-and-grade is unmeasurable, and a ~2.5-hour market-hours data outage would permanently tombstone every open idea. The conviction lane's "HARD-block" from trading is a code comment, not code.

## 2. What held up under attack (verified, stop worrying)

- **The LLM cannot alter structure-lane numbers.** The accepted idea copies entry/stop/targets from the detected structure dict only (`ai/research/setup_scan.py:316-343`); the verdict contributes text + a structure-type *selection* among detected structures (`:469-478`); the ranker can only reorder — unknown symbols are ignored, omitted ideas are re-appended (`:516-534`); LLM-supplied `origin` is stripped and re-stamped server-side (`ai/research/ideas.py:77`, `:249`). Prompt-injected web text can veto/DoS or poison prose, not prices.
- **No lookahead in S/R.** `swing_pivots` sees only `bars[:idx+1]` and the most recent `window` bars can never be pivots (`research/levels.py:8-45`); `level_features` orders `support_prices` nearest-first descending / `resistance_prices` nearest-first ascending (`:122-128`), matching exactly what `structures.py` assumes.
- **Degenerate inputs fail closed.** Non-positive/garbage prices dropped (`ai/research/structures.py:33-42`); inverted or non-positive stops rejected (`:149`, `:215`); no targets → no structure; the R/R≥1.5 floor is enforced pre-rounding on both detectors (`:158`, `:224`); penny-stock cent-rounding can only *reject* an idea at validation (rounded stop ≥ rounded entry_low), never emit inverted numbers.
- **Weekend kill-bug: genuinely fixed.** `fetch_daily_bars_since` is honestly tri-state (`ai/research/data_sources.py:113-129`): `None` = fetch failed, `[]` = fetch OK but no session on/after `as_of`. The empty case clears the failure streak so a closed market can never accrue toward `data_gap` (`research/idea_tracker.py:304-310`). (But see M-6: the same branch skips time-based expiry.)
- **RVOL dedup persistence: correct.** Keyed `rvol:{symbol}:{ET-date}` in `earnings_alerts_sent` (`api/main.py:827-841`), date computed in ET (`:875`), marked only *after* a successful `notify` (`:910`) so a failed push retries next tick; no key collision with earnings keys (`{SYM}:{date}:{milestone}`, `:985` — symbols can't contain `:`). Worst case is one duplicate if the process dies between notify and mark. Growth is one tiny row per alert per day — no correctness bug hiding in it (see L-3 for the hygiene nit).
- **A/B journaling surface exists end-to-end.** `origin` column with server-side default (`db/idea_outcomes.py:60-62`), per-origin win-rate split in `get_summary` (`:275-293`), origin chips in the widget (`frontend/components/workspace/widgets/idea-outcomes-widget.tsx:80-107`), `data_gap` excluded from win-rate ✓.

## 3. Ranked findings — 1 CRITICAL · 2 HIGH · 6 MEDIUM · 6 LOW

### CRITICAL-1 — The "conservative same-bar" rule is a one-sweep illusion: ambiguous bars become WINs
`research/idea_tracker.py:140-160` documents the honesty invariant: *"zone + target in one bar = the run to target may have happened BEFORE the dip into our zone → only TRIGGERED; a win needs a later bar to prove it."* `_process_pending` duly returns `triggered` without checking targets. But `_process_triggered` re-fetches bars since `as_of` and its loop admits the **trigger bar itself** (`:215` skips only `bar_date < trigger_date`), then awards the win from it (`:241-249`). **Reproduced live:** one bar (zone 100–105, target 110, bar low 102 / high 111) → sweep 1: `triggered`; sweep 2, thirty minutes later, same bar: `won`, `resolution_price=110`, `resolved_at == triggered_at`. The sweep runs every 30 min in market hours (`api/main.py:213`), so every ambiguous bar converts to a WIN within the hour. This inflates the exact number the whole mission gates on — journal win%, the A/B comparison, and the future calibration-gated `entry_mode=auto` promotion. The test suite enshrines the illusion: `tests/test_idea_tracker.py:177` asserts only the *first* sweep. Compounding: pullback targets are filtered `> zone_high`, not `> close` (`ai/research/structures.py:152`), so a "forming" idea can carry a target *below the current price* — a free instant win under this bug.
**Fix:** in `_process_triggered`, require `bar_date > trigger_date` for the target-win path (keep the stop check as-is — a same-bar stop was already resolved as `lost` in pending), and add a second-sweep regression test.

### HIGH-1 — Vetoed setups are never outcome-tracked: the veto half of "veto-and-grade" has no report card
Only validated ideas reach `register_ideas` (`ai/research/setup_scan.py:1082-1097`); a veto ends the candidate at `:456-461` with a text reason in the scan JSON and nothing else. The constitution is explicit — *"every card — incl. declines — recorded, graded, fed back"* — and the founder's standing rule is calibration-counts-everything. As shipped, an LLM that drifts into vetoing every good structure would be invisible: structure-lane win% stays clean while the funnel silently starves, and there is no data to ever answer "do the vetoes add value?" The deterministic levels are already in hand at veto time (the `structure` dict), so tracking costs one line of plumbing.
**Fix:** register vetoed structures with `origin="structure_vetoed"` (same mechanical sweep, excluded from the tradable lane), giving the veto an A/B against `structure` for free.

### HIGH-2 — A ~2.5-hour market-hours data outage permanently tombstones every open idea
`DATA_GAP_FAIL_STREAK = 5` (`research/idea_tracker.py:18`) counts consecutive *sweeps*, not elapsed time. At the 1800s market-hours interval (`api/main.py:213`), five failed fetches ≈ 2.5 hours of Alpaca (or network) outage — and an outage fails **all** open rows in lockstep, so every open idea crosses the threshold on the same pass and is marked `data_gap` (`idea_tracker.py:289-300`), a terminal status (`db/idea_outcomes.py:18-20`) with no resurrection path. The streak is persisted, so restarts don't reset it. The weekend-kill bug was fixed; this is its surviving sibling — same blast (sample destruction, silent), different trigger. Mitigation in place: `data_gap` is excluded from win-rate, so it biases the sample size, not the ratio.
**Fix:** gate `data_gap` on elapsed *trading days* of failure (e.g., ≥3) rather than tick count, or make `data_gap` reopenable when bars reappear.

### MEDIUM-1 — Same-day retroactive judging: the creation-day bar includes pre-publication price action
`_process_pending` admits bars with `bar_date >= as_of_date` (`research/idea_tracker.py:123`) — the *full* creation-day bar. An idea published at 3pm inherits the morning's action: a pre-publication dip through zone + stop marks it `lost` (`:146-154`); a pre-publication crash through the stop without zone-touch marks it `invalidated` (`:162-169`); and a "ready" pullback (close already inside the zone, `structures.py:139-141`) triggers instantly off action that predates the idea. Direction is mostly deflationary (the opposite of CRITICAL-1) but it's still judging ideas on price action that happened before they existed — the calibration ledger should measure the idea, not the morning.
**Fix:** when `as_of` carries an intraday timestamp, start judging from the next session (or intersect the creation-day bar from the as_of time using intraday bars).

### MEDIUM-2 — The probability validator: real bypasses + unscanned fields
The fixed regex (`ai/research/ideas.py:16-20`) correctly catches `"70% win rate"` / `"win probability 70%"` while passing benign `"1.0% above support"`. Verified bypasses: **"a 70 percent chance of success"** (spelled-out percent), **"roughly 0.7 probability"** (decimal, digits before keyword), **"7 times out of 10"**, **"7 in 10 odds"**, **"confidence score: 9/10"**. And the scan covers only `thesis` + `confidence_reason` (`:103`) — `risks[]`, `why`, and the ranker's `scan_note` are never checked, so a numeric probability in a risk bullet ships to the paper and phone untouched.
**Fix:** add spelled-out-percent / X-in-Y / X-out-of-Y / bare-decimal-probability patterns; scan `risks[]` and `scan_note` too.

### MEDIUM-3 — The conviction lane's "HARD-block" from trading is a comment, not code
`ai/research/setup_scan.py:993-995`: *"HARD-blocked from proposal/arming — Phase 5c bridge (#42) must filter origin != 'structure' before any trade path."* Verified: no such filter exists anywhere, and today no bridge consumes ideas at all (`entry_condition`/`price_in_zone` has zero consumers outside `ideas.py`), so the block is currently *vacuous* — enforced by absence, not by code. Meanwhile conviction ideas ride in the same `report["ideas"]` array (`:1017-1018`, `:1047`) and the same `idea_outcomes` table as structure ideas, distinguished only by a string field a future bridge author must remember to check. This is precisely the pattern the chokepoint discipline exists to prevent.
**Fix now, before #42:** one choke function (e.g., `tradable_ideas()` filtering `origin == "structure"`) that any future bridge must import, plus a test asserting `llm_conviction` never passes it.

### MEDIUM-4 — Conviction-lane numeric guards are thin: no R/R floor, grounding is prompt-only
The structure lane enforces R/R ≥ 1.5 (`structures.py:28`, `:158`, `:224`). Conviction ideas — where the LLM authors every price — pass validation with only stop < entry_low, targets > entry_high, and the ±25% entry / ±40% stop sanity bands (`ideas.py:177-196`): an R/R-0.2 idea validates. The prompt's *"prices MUST be grounded in the provided support/resistance levels"* (`setup_scan.py:79-81`) has no code counterpart — nothing checks proximity to any provided level. Contained by design (lane is journal-only, capped at 2, allowed-symbols enforced), but the A/B this lane exists for compares lanes held to *different quality floors*, which will muddy the verdict it's supposed to produce.
**Fix:** apply the same R/R≥1.5 floor to conviction ideas, and reject conviction prices further than ~2% from every provided S/R level / latest_close anchor.

### MEDIUM-5 — Ranker failure aborts the scan after validation; "discarded" ideas appear twice
A ranker LLM failure raises `RuntimeError` (`setup_scan.py:962-963`) → the whole run is marked failed → `register_ideas` never executes: fully-validated, deterministic ideas are dropped from outcome tracking because a *display-ordering* call hiccupped (counts-everything violated by the least important step). Separately, ranker "discards" only decorate: the symbol stays in `validated_ideas` (reorder-only, `:516-534`) *and* is listed under "No-setup candidates" (`:1028`) — the same symbol shipped as both a ranked idea and a no-setup in one paper.
**Fix:** fail-soft the ranker (keep deterministic order, note the failure); either honor discards as real drops (still registering them for tracking) or stop printing them in no-setup.

### MEDIUM-6 — Halted/renamed symbols leave ideas open forever: the empty-bars branch skips expiry
When the fetch succeeds but returns no session on/after `as_of`, the sweep returns early (`idea_tracker.py:304-310`) without ever reaching the pure-time expiry checks (`:178`, `:262`). For a weekend that's the fix working as intended; for a symbol halted or renamed after registration (old bars exist → fetch "succeeds" → filtered list is `[]` forever) the idea never expires. **Reproduced:** 10 weeks past a 10-trading-day TTL, still `pending`. Doesn't distort win% (open rows are excluded) but accretes zombie rows swept forever.
**Fix:** apply the `now_date >= expiry_date` check in the empty-bars branch too.

### LOW findings
- **L-1** `_add_trading_days` ignores market holidays (`idea_tracker.py:46-57`) — TTL clocks run ~1 day hot around holidays; and expiry is checked *after* zone/stop within the loop (`:131` vs `:171`), so a bar on the expiry date can still trigger.
- **L-2** R/R floor is measured at zone-mid (`structures.py:156-158`); a worst-case fill at zone_high passes the gate below 1.5. Disclosure nit — consider floor-at-zone-high.
- **L-3** `earnings_alerts_sent` grows unbounded — `db/retention.py` never touches it. Rows are tiny (key + timestamp) so this is hygiene, not a bug; one `DELETE WHERE created_at < -90d` line in the retention pass closes it.
- **L-4** `evidence` accepts arbitrary strings with no URL-scheme allowlist (`ideas.py:207-210`) and the paper editor renders them as links — prompt-injected web content can plant phishing URLs in a founder-facing report. Allowlist `http(s)://`.
- **L-5** The veto-grade payload is truncated by raw char-slice `json.dumps(payload)[:N]` (`setup_scan.py:429-431`) — can cut JSON mid-token. Structures sit early in the payload so numbers are unaffected; degraded prompts, not corrupted levels.
- **L-6** Breakout's `distance_to_zone_pct` metric actually reports distance *below resistance* (`structures.py:239`) while pullback's reports distance above the zone (sign-flipped semantics per type) — confusing to any future consumer that compares them.

## 4. Bottom line

The generation half of the engine survived the adversarial pass: numbers are code-owned, levels are point-in-time, the LLM's only real powers are veto, grade, and reorder — as designed. The judging half is where the constitution leaks: **fix CRITICAL-1 before the journal accumulates poisoned wins** (it's a one-line comparison change plus a test), then HIGH-1/HIGH-2 to make the veto measurable and the sample outage-proof. Until CRITICAL-1 lands, treat every `won` whose `resolved_at == triggered_at` as suspect — that predicate also identifies exactly the rows to re-judge retroactively.
