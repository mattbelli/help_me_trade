## 🔴 NEW — mobile chat is rendering raw tool-call XML (serv-side bug, needs your fix)

Founder hit this live (screenshot): the assistant bubble printed literal
`<function_calls><invoke name="get_agent_status">…<invoke name="web_search">…</function_calls>`
instead of an answer.

**Not a client bug** — our SSE parser is correct (see audit Q1) and we faithfully render the
`text-delta` content you stream. **Root cause is serv-side in the mobile brain:**

- `ai/chat/mobile_agent.py:150` does the final answer as a plain `get_llm().complete(final_messages)`.
- `final_messages` is built by `ai/chat/agent.py::_build_final_messages`, which sets
  `system_content = _system_prompt()` (`agent.py:158`).
- `_system_prompt()` advertises the full tool catalog (`Available tools:\n{tools}`, `agent.py:141`) and
  instructs the model to *call* them ("Use the tool API and wait for results", `agent.py:112`).
- But that final `complete()` has **no native tool-parsing** (unlike the web brain's `ai/chat/loop.py`).
  So the model "calls" its tools the only way plain text allows — by emitting the `<function_calls>` XML —
  and it streams straight through `_text_delta_events` to the client as message content.

**Recommended fix (serv-side, your call which):**
1. *Minimal:* give the final synthesis `complete()` a **tools-free** system prompt — a synthesis variant
   that says "write the answer from these tool results" and does NOT list tools or tell the model to call
   them. i.e. `_build_final_messages` should not reuse the agentic `_system_prompt()` verbatim for the
   non-tool-calling final turn.
2. *Better (the migration already flagged in your handoff §"is mobile on the unified brain? No"):* move
   mobile onto `ai/chat/loop.py` so tool-calls are real/iterative and never leak as text.

**Client mitigation already shipped (mac side):** `mobile/src/features/chat/strip-tool-markup.ts` scrubs
any `<function_calls>`/`<invoke>`/`<parameter>` markup from assistant text before render (applied in
`chat-bubbles.tsx`). This is defense-in-depth only — with the leak present the founder now sees the intro
sentence and no answer body (better than XML, still not a real answer). Your prompt fix is the real one.
